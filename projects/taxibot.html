TaxiBot

A natural-language business-intelligence copilot that plans SQLite queries, executes them over a deterministic taxi dataset, selects a visualization, and explains the result.

The problem

Business questions should not wait for dashboard rebuilds.

TaxiBot explores a product pattern for self-service analytics: let a user describe the decision in plain English, expose the data schema to the model, and return an inspectable SQL query alongside the chart and explanation.

Product boundary

The included 50,000-row dataset is synthetic and seeded for reproducibility. It demonstrates the interaction and analytics system without presenting generated records as official NYC TLC data.

System design

One structured response controls the query, chart, and explanation.

  1. Capture the question

    Streamlit presents suggested analyses, maintains multi-turn conversation state, and accepts a free-form business question.

  2. Plan against the schema

    Groq-hosted Llama 3.3 70B receives the exact SQLite schema and returns JSON containing SQL, chart type, title, axes, and an insight.

  3. Execute and shape

    SQLite runs the query and Pandas produces a consistent table for downstream rendering.

  4. Render the answer

    Plotly dispatches bar, line, scatter, pie, histogram, or heatmap views while the interface preserves the raw query result.

Product decisions

Designed for inspectability, not a black-box answer.

Schema-grounded planning

The system prompt enumerates every available field and constrains the response to a known JSON contract. That lets the interface handle model output as a plan rather than an unstructured paragraph.

Zero-setup evaluation data

A fixed random seed creates the database on first run, including indexes for hour and borough. Reviewers can reproduce the same product behavior without downloading a dataset.

Chart dispatch

The LLM proposes the visualization, while deterministic Python code owns the actual Plotly construction and theme.

Limits & hardening

The next production steps are explicit.

  • Add a SELECT-only SQL parser and run the database connection in read-only mode before using the pattern with sensitive data.
  • Validate generated column names and the full response against a typed schema before execution.
  • Add golden-question evaluation for SQL correctness, chart choice, and explanation faithfulness.
  • Replace the demonstration data with governed warehouse access and row-level permissions for a production deployment.

ClientPulse

A synthetic multi-client reporting dashboard with an internal portfolio view, a polished client-facing pitch view, shared KPI definitions, SQL quality gates, and auditable refresh behavior.

The problem

Internal decisions and client conversations need the same numbers-but different emphasis.

Account teams need cross-client comparisons and portfolio anomalies. Clients need a focused view of their own performance. ClientPulse separates those experiences while preserving a shared analytical model for leads, conversions, attributed revenue, media spend, and campaign return.

Measurement boundary

Campaign return is attributed revenue relative to media spend. It is not presented as incremental or causal ROI, and all accounts and values are fictional.

System architecture

An atomic refresh publishes data only after every quality rule passes.

01 / SOURCECampaign factsFour accounts, three campaigns, and 12 months.
02 / STAGECandidate databaseA refresh is isolated from the approved reporting layer.
03 / TESTSQL quality gateFourteen grain, range, and consistency checks.
04 / PROMOTEApproved datasetPassing data replaces the prior SQLite database atomically.
05 / SERVETwo dashboardsPortfolio management and scoped client pitch views.

Engineering decisions

Trust is designed into the reporting workflow.

Ratios use summed components

Portfolio conversion rate and campaign return are calculated from total numerators and denominators, avoiding misleading averages of pre-aggregated percentages.

Failed refreshes do not overwrite approved data

The pipeline stages candidate data, runs all SQL checks, and promotes only a passing database. Every attempt records time, source hash, row count, issue counts, status, and KPI totals.

Filtering happens in the query

The pitch view uses a parameter-bound server-side SQL query and regression tests confirm it returns only the selected account. This is scoped filtering, not authentication or authorization.

Evidence & outputs

The same metric layer supports two reporting jobs.

  • Account manager view with portfolio KPIs, client and channel comparisons, trends, KPI detail, and refresh controls.
  • Client-pitch proof of concept with focused channel performance and monthly conversion trends.
  • Documented KPI and data dictionaries plus design and refresh rationale.
  • Pipeline, KPI, account-scope, and Streamlit page regression tests.

Limits & next steps

The public demo is intentionally not a client portal.

  • All four accounts and performance values are synthetic and visible to every visitor.
  • Streamlit login alone would identify a user but would not create authorization.
  • A production release would require a trusted user-to-client entitlement map, deny-by-default query scoping, protected exports, durable monitoring, and scheduled refresh infrastructure.

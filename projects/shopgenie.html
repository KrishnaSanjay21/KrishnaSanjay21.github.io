ShopGenie-E

A LangGraph shopping workflow that turns intent, use case, and budget into live product research, a requirements-based Genie Score, and a structured comparison dashboard.

The problem

Product search returns options; purchasing requires a decision.

ShopGenie-E is designed around the missing reasoning layer between search results and a confident choice. It collects the shopper's use case and budget, researches current candidates, and converts product specifications into ranked trade-offs.

Decision-support principle

The product does not stop at a recommendation name. Each option includes a score, best-fit rationale, translated benefits, technical specifications, and an explicit dealbreaker.

Agent architecture

Specialized nodes share one typed workflow state.

  1. Intent and context manager

    Classifies greetings, recognizes a buying request, extracts the use case, and requests a budget when the constraint is missing.

  2. Retrieval agent

    Uses Tavily to search product and retailer sources for up to eight current candidates and review signals.

  3. Reasoner agent

    Groq-hosted Llama 3.3 70B converts the evidence into three structured options with prices, fit summaries, specifications, and 0–10 scores.

  4. Image fetcher

    Runs a targeted image search for each selected product and attaches imagery to the structured recommendation.

  5. Evaluator

    Checks that the final recommendation parses as JSON and routes malformed output back through retrieval.

Interface design

Agent output becomes an explorable comparison, not a chat transcript.

Streamlit renders the top three products as Powerhouse, Balanced, and Budget cards. Pandas builds the comparison table, while selection state opens a deep dive containing the fit rationale, specifications, benefits, gallery, dealbreaker, and purchase link.

Conversation memory

The most recent messages are passed back into the intent stage so a shopper can state their use case, product category, and budget across separate turns.

Limits & hardening

Fresh web data creates useful—and testable—failure modes.

  • Replace JSON parse-only evaluation with a typed schema that validates required fields, score bounds, URLs, and evidence provenance.
  • Cap evaluator retries so malformed model output cannot create an unbounded retrieval loop.
  • Attach source citations and freshness timestamps to each product claim and price.
  • Add offline fixtures and agent-level evaluations for intent routing, budget extraction, ranking stability, and dealbreaker quality.
Next milestone

Make ranking evidence traceable from each displayed claim back to the retrieved source, then evaluate recommendation consistency over a fixed shopping-query set.

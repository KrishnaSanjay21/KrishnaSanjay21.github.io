DataLens

A zero-configuration Streamlit application that profiles an uploaded CSV, ranks quality issues, explains statistical signals, and builds an interactive exploratory report without sending data to an LLM.

The problem

Useful EDA should begin before a notebook is configured.

Analysts repeatedly write the same first-pass code to inspect types, missing values, duplicates, distributions, outliers, and correlations. DataLens packages that work into one deterministic flow so a new dataset can be assessed immediately and the highest-risk quality problems surface first.

Product principle

Every plain-English finding is derived from measured statistics and explicit rules. The application does not invent explanations or require an external inference service.

System architecture

One in-process pipeline turns a CSV into an explorable report.

01 / INPUTCSV or samplesUser upload, Titanic, Iris, or NYC Taxi.
02 / SCHEMAType inferencePandas identifies numeric and categorical fields.
03 / PROFILEStatisticsShape, missingness, duplicates, skew, kurtosis, cardinality.
04 / DIAGNOSERule engineSeverity-ranked findings and recommendations.
05 / PRESENTPlotly reportCharts, tables, search, and CSV download.

Engineering decisions

Determinism, privacy, and useful defaults shape the product.

Severity instead of an unranked checklist

Constant columns, heavy missingness, duplicate rates, outliers, skew, and high cardinality are assigned explicit thresholds so users can distinguish blockers from minor warnings.

Charts follow column semantics

Numeric fields receive histograms, mean/median overlays, box plots, correlations, and scatter matrices. Categorical fields receive frequency and share views rather than inappropriate continuous plots.

Local analysis boundary

Pandas, NumPy, and Plotly operate in the application process. Uploaded values are not forwarded to an LLM, and no API key is necessary.

Evidence & outputs

The result is an analysis workspace, not a static score.

  • Searchable raw-data preview with column selection and CSV export.
  • Ranked data-quality warnings covering missing values, duplicates, outliers, skew, constant fields, and cardinality.
  • Descriptive statistics enriched with skewness and kurtosis.
  • Interactive distributions, categorical breakdowns, correlation heatmap, and scatter matrix.

Limits & next steps

Automated profiling accelerates judgment; it does not replace it.

  • CSV type inference can misclassify identifiers, dates, and numeric codes without domain metadata.
  • Fixed thresholds are transparent but may need per-domain configuration.
  • Large files remain bounded by Streamlit process memory and browser rendering cost.
  • A stronger release would add schema overrides, sampled profiling, reproducible report snapshots, and tests for every diagnostic threshold.
Next milestone

Add a schema-confirmation step and exportable report manifest so each finding records the field, rule, threshold, observed value, and recommended action.
